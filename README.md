# 网络系统管理赛项知识库问答助手

一个基于 **RAG（检索增强生成）** 的本地知识库问答系统，**仅使用 Python 标准库实现**，不依赖任何第三方包。

## 项目背景

准备「网络系统管理」赛项时，手头有 4 份资料（赛题样题、模块试题、技术文档），共约 4 万字。
想查「B 模块的 DHCP 中继怎么配」，需要在 PDF 和 Word 里反复翻找，耗时数分钟。

本项目把这些资料做成可问答的知识库：**输入问题，系统从资料中检索相关段落，
由大模型基于资料回答，并标注答案来源。**

## 技术方案

```
原始资料 (PDF / Word)
        ↓  ① 文本提取
     纯文本
        ↓  ② 清洗修复
   规整文本
        ↓  ③ 切块（标题层级 + 面包屑）
   131 个知识块
        ↓  ④ 中文分词 + TF-IDF 建索引
      索引
        ↓  ⑤ 检索 Top-3         ← 用户提问
   相关段落
        ↓  ⑥ 拼提示词 + 调用 LLM
     带来源的回答
```

## 核心实现

### ① 文档提取

| 格式 | 方案 |
|---|---|
| PDF | `pdftotext -layout` |
| Word (.docx) | Python 标准库 `zipfile` + `xml.etree`（docx 本质是 zip 包，正文在 `word/document.xml`） |

### ② 清洗修复

从 PDF 抽取的文本有两类缺陷，若不修复会导致切块错位：

- **标题被吞进上一段**：如 `...密码皆为：ChinaSkills23。1．DCserver 系统基础环境配置`
  被合并为一行。用正则 `([。；])\s*([0-9]+[．、.](?=[^\d]))` 重新断行，
  并利用 `(?=[^\d])` 排除 `8.8.8.8` 这类 IP 地址被误切。
- **目录污染**：目录包含全部标题文字，会导致任何查询都命中目录块（假阳性）。
  识别并整体剔除目录区。

### ③ 切块策略

不按固定字数硬切（会从中间劈断配置说明），而是**按文档天然的标题层级切块**，
并为每块附加所属章节路径（面包屑）：

```
面包屑：模块 B-服务部署 › （一）DCserver 配置任务 › 4．DHCP SERVICE
正文：  安装及配置 DHCP 服务；创建一个名为"ChinaSkills.cn"的 DHCP 作用域...
```

结果：4 万字 → **131 个语义完整的知识块**（平均 274 字）。

### ④ 中文分词（自己实现）

中文没有空格，检索前必须分词。实现三步：

1. **字符分类**：区分中文 / 字母数字与小数点 / 其他
2. **按类型分组**：把连续同类字符攒成一段（类型变化时收尾）
3. **中文二字切分**：相邻两字组成一个词（bigram）

```
tokenize("配置DHCP服务")  →  ['配置', 'DHCP', '服务']
tokenize("172.16.100.221") →  ['172.16.100.221']     ← IP 不被切碎
```

### ⑤ TF-IDF 加权检索

朴素做法是「命中一个查询词加 1 分」，但会被常见词严重干扰：

```
问题："怎么配置WSUS更新服务"
分词：['怎么', '么配', '配置', 'WSUS', '更新', '新服', '服务']
                      ↑ 出现于 74 个块        ↑ 出现于 2 个块
                       没有区分度                极强区分度
```

引入 IDF 加权：**一个词出现的块越少，权重越高。**

```
权重 = 总块数 ÷ 出现该词的块数

WSUS  → 131 / 2  = 65.5
配置  → 131 / 74 =  1.8
```

改进后，Top-1 与后续结果的分数差距显著拉开（如 `VLAN修剪` 从 2:1 变为 152.8:21.8）。

### ⑥ 幻觉防护

提示词中设置三条硬约束：

```
1. 只能使用资料中的内容，不要使用你自己的知识
2. 如果资料中没有答案，直接回答「资料里没有找到相关内容」
3. 回答末尾标注依据的是哪几条资料
```

**已验证**：询问「今天天气怎么样」「怎么用 Python 写爬虫」时，
系统均正确回答"资料里没有找到相关内容"，未发生编造。

### ⑦ 效果评测

构建 **28 题人工标注测试集**，分两组对比：

| 组别 | 说明 | Top-1 | Top-3 |
|---|---|---|---|
| **A 组：直接提问** | 问题使用原文术语（如"DHCP中继怎么配"） | **100%** | **100%** |
| **B 组：改写提问** | 用同义表达，不出现原文术语（如"怎么让客户端自动获取IP"） | 75% | 75% |

```bash
python3 eval_retrieval.py
```

**评测暴露的真实短板**（这是本项目最有价值的发现）：

| 失败案例 | 期望答案 | 根因 |
|---|---|---|
| 怎么限制员工上班时间**玩游戏** | P2P 应用阻断 | 语料原文是"P2P 应用软件"，**无"游戏"一词** |
| 怎么让**外网**访问**内网**服务 | NAT 配置 | 语料原文是"内部客户端访问**互联网**"，**用词完全不同** |

**两个失败案例根因相同：关键词检索对「同义表达」不敏感。**

这是关键词检索的固有局限，无法通过调参解决，**需引入向量检索（Embedding）
做混合检索**——已列为下一步改进方向。

> 💡 这个「知道自己的系统哪里不行、为什么不行」的结论，
> 比一个漂亮的准确率数字更有工程价值。

### ⑧ MCP 工具封装

将自研检索能力封装为**标准 MCP Server**，可被 Claude Desktop / Cursor / Cline
等支持 MCP 的 AI 应用直接调用。

**MCP 协议本质**：JSON-RPC 2.0 over stdio —— 从标准输入读消息、往标准输出写消息。

**核心方法实现**：

| 方法 | 作用 |
|---|---|
| `initialize` | 握手，返回协议版本与能力声明 |
| `tools/list` | 返回工具清单（含 `inputSchema`） |
| `tools/call` | 执行工具，结果以 `content` 数组返回 |

**零依赖实现**：使用 Python 标准库 `sys` / `json` 完成，未引入 `mcp` SDK。

```bash
python3 test_mcp.py     # 测试客户端：完整走一遍握手 → 列工具 → 调用
```

**实测输出**：

```
✅ initialize 握手成功，服务器：knowledge-base-server v1.0.0
✅ 服务器提供 1 个工具：search_knowledge_base
✅ tools/call 返回检索结果（相关度 84.2，来源块 #20）
```

## 运行

**环境要求**：Python 3.x、系统安装 `poppler-utils`（提供 `pdftotext`）。**无需 pip 安装任何包。**

```bash
# 1. 从原始资料生成知识块
python3 build_corpus.py      # 提取文本（输出到 corpus/）
python3 clean_text.py        # 清洗修复（输出到 clean/）
python3 chunk_docs.py        # 切块（输出 chunks.json）

# 2. 检索效果评测（不需要 API key）
python3 eval_retrieval.py

# 3. 测试 MCP Server（不需要 API key）
python3 test_mcp.py

# 4. 启动问答
export DEEPSEEK_API_KEY=sk-你的key
python3 rag.py
```

## 已知局限与改进方向

- **语料局限**：原始资料是赛题样题，内容以「任务要求」为主，
  缺少「配置步骤」。后续可补充设备配置手册以提升实用性。
- **检索方式**：当前基于关键词 + TF-IDF，对同义改写的查询命中率有限。
  可引入向量检索（Embedding）做混合检索。
- **无界面**：目前为命令行交互，可加 FastAPI 接口层与 Web 前端。
