# 学习示例

这里的文件**不属于项目功能**，是学习过程中写的演示代码，
用来理解某些概念"到底是怎么运作的"。

每个文件都可以直接运行，看输出比看讲解更清楚。

```bash
cd ~/rag-project
source .venv/bin/activate
python3 examples/xxx.py
```

## LangGraph 相关

按顺序看，后面的依赖前面的概念。

| 顺序 | 文件 | 讲什么 | 你会看到 |
|---|---|---|---|
| 1 | `langgraph_01_基础三概念.py` | State / Node / Edge | 数据怎么从一个节点流到下一个 |
| 2 | `langgraph_02_状态累积.py` | 状态是**累积**的 | 每个节点看到的都是"改过之后"的最新状态 |
| 3 | `langgraph_03_合并器.py` | 覆盖 vs 追加 | 同一个字段，两种合并规则的差别 |
| 4 | `langgraph_04_三场景对比.py` | 三种情况并排对比 | 覆盖、追加、空字典，一次全看到 |

### 核心结论

**节点返回的字典 = 一张「改动清单」，不是完整的新状态。**

| 清单里写了什么 | 框架怎么处理 |
|---|---|
| 某个字段有新值 | 按该字段的**合并器**合并 |
| 没提某个字段 | **保持原样**，不动 |
| 是个空字典 `{}` | **什么都不改** |

**而「合并器」决定"有新值"时是覆盖还是追加：**

| 合并器 | 效果 | 适合 |
|---|---|---|
| 不指定（默认） | **覆盖**（新的替换旧的） | `name`、`score` 这类"当前值" |
| `append_list` | **追加**（新的接在后面） | 对话历史这类"累积"的数据 |

**这解释了为什么 LangGraph 的 agent 示例里，`messages` 字段要写成：**

```python
messages: Annotated[list, add_messages]
```

因为对话历史必须**累积**，如果默认覆盖，新一轮对话会把前面的全冲掉。
